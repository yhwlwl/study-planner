# v0.8.12 Proposal Preview Layout Fix

## Problem

The mobile proposal preview mixed event explanation, product-policy explanation, a single selectable proposal, and sticky actions inside one scroll container. The result was repeated information, a fake choice when only one local operation existed, and content scrolling underneath the primary button.

## Implementation

1. `Modal` now accepts an optional `footer` node rendered outside `.modal-body`.
2. `ProposalDialog` passes its action buttons through that footer.
3. A single explicit local operation skips the proposal selector and renders `LocalOperationResult`.
4. The primary button derives its label from `requestedChangeLabel`.
5. “More alternatives” becomes a secondary opt-in action.
6. Mobile CSS restores the full-screen modal to `100dvh` after the more specific `modal-wide` rule.

## Compatibility

No schema, persistence, scheduling, migration, or execution-record behavior changed.
