# Android Edge / PWA 滚动与游客重置热修复

## 1. 每日任务无法纵向滚动

已确认每日任务卡此前直接使用 HTML5 `draggable=true`。部分 Android Chromium / Edge，尤其以桌面图标/PWA 方式启动时，手指从可拖拽元素开始纵向滑动会被原生拖拽手势抢占。

修复后只有 `(hover: hover) and (pointer: fine)` 的桌面指针环境启用任务卡原生拖拽；触屏设备禁用原生拖拽，点击、完成、计时等操作不受影响，页面继续使用纵向滚动。

## 2. 游客空间“重置计划”无效

问题属实。设置页在游客数据空间点击“重置计划”时实际调用的是 `resetAll('demo')`，确认后会重新载入演示模板，因此用户会感觉完全没有重置；导出 JSON/CSV/PDF 只是备份动作，并不是重置开关。

热修复在游客空间截获该危险操作并明确调用 `resetAll('blank')`。独立的“恢复演示计划”按钮仍负责恢复示例数据。登录账号原有的空白重置逻辑保持不变。

## 回归验证

新增 `tests/mobile-edge-reset-regression.test.tsx`，覆盖触屏不启用原生拖拽、桌面仍启用拖拽，以及游客重置按钮识别不误伤“恢复演示计划”。
