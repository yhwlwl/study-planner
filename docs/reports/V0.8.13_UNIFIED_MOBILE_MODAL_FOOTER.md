# v0.8.13 Unified Mobile Modal Footer

## Architecture

`Modal` now recursively inspects the trailing child path. When the last semantic child has class `modal-actions`, it is removed from the body tree and rendered as `modal-footer`.

Explicit `footer` props take precedence and are not auto-extracted.

## Layout contract

```text
modal-card (flex column, overflow hidden)
├─ modal-header (flex none)
├─ modal-body   (flex 1, min-height 0, overflow-y auto)
└─ modal-footer (flex none, safe-area owner)
```

This removes the previous dependency on per-page sticky action blocks.

## Mobile action layout

- 1 action: full row.
- 2 actions: compact secondary + flexible primary.
- 3 actions: two secondary actions + full-width primary row.
- Explicit proposal footer retains its event-specific layout.

## Compatibility

The recursive extraction supports:

- direct trailing action rows;
- fragments;
- wrapper components whose last child is an action row;
- conditionally rendered trailing action rows.

No domain or persistence changes are introduced.
