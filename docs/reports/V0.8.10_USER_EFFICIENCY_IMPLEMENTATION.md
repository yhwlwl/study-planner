# Study Planner v0.8.10 用户效率实现说明

## 1. 目标

v0.8.10 不新增调度概念，重点消除真实使用中的数据不可信、任务找不到、重复确认、无关提问和设置暴露问题。

统一原则：

1. 简单操作只做用户明确要求；
2. 已发生的实际记录必须可靠保存；
3. 同一数字必须使用同一口径；
4. 所有任务必须有稳定可发现入口；
5. 系统预览只保留一个真正确认点；
6. 高级能力保留，但默认折叠。

## 2. 计时与完成

- Today 任务卡检测到活动计时器时，不再直接进入普通完成弹窗，而是返回统一计时结束流程。
- Today 完成处理保留陈旧状态兜底：若仍检测到该任务的活动计时器，且用户未另填分钟，则把当前累计秒数四舍五入为分钟写入 `timeEntries`，来源为 `timer`。
- 计时器只有在时间成功记账后才清空。

## 3. 统计口径

- 将每日聚合提取为纯函数 `src/lib/stats.ts::aggregateDaily`。
- 先累计 `timeEntries`，再仅计算一次 `actualMinutes - recordedMinutes` 的正残差。
- 增加运行级回归：40 分钟计时明细 + 20 分钟旧残差 + 30 分钟纯旧记录，结果必须为实际 90、计时 40、旧记录 50。
- 热力图使用正值的第 90 百分位作为尺度，避免单个极端长日压平其余日期。

## 4. Today 信息口径

Today 分开显示：

- 原计划；
- 已发生实际；
- 剩余预计；
- 执行负载／容量。

风险判断统一使用 `planningDayLoad(state, date)`，即真实执行状态与剩余工作共同构成的执行负载。

过去、今天和未来日期使用不同文案；未来日期不再显示“结束今天并复盘”。

## 5. 任务可发现性

原“全部任务”改为“任务”，内部拆成：

- 具体任务；
- 任务组。

具体任务提供：

- 待处理；
- 未安排；
- 逾期；
- 今日；
- 未来；
- 已完成；
- 全部。

“仅保存复盘，暂不顺延”的任务继续保留原日期，并集中出现在“任务 → 待处理”；Today 也会显示过去未完成任务提醒。

## 6. 减少重复步骤

- 批量顺延首屏改为“设置”，按钮改为“生成完整预览”；统一预览是唯一最终确认点。
- 任务、任务组、目标和日期约束删除直接进入统一影响预览，不再叠加前置确认。
- 批量移动取消浏览器 `prompt`，改用日期选择器、任务数量和可展开任务清单。
- JSON 导入、云端恢复和同步冲突备份恢复统一先显示覆盖差异，再确认。

## 7. 局部编辑

- 任务标题改为草稿，一次保存，不再每个字符占用撤销历史。
- 日期备注改为草稿，随日期设置一次提交。
- 修改任务时长的第一方案只改变时长并保持日期；只有新增或恶化问题才要求处理。
- 应用方案和复盘当前方案后提供就近“撤销”，无需进入设置页。

## 8. 渐进式设置与表单

- 排期算法参数和恢复维护默认折叠。
- Supabase 未配置时不展示账号同步区，也不向普通用户显示环境变量名。
- 任务组高级规则默认折叠。
- 目标的特殊单项任务关联默认折叠，只有已选时自动展开。
- “今天还能接收多少新任务”只在当前问题修复或未来重组且确实涉及今天时询问；减负与复盘差异不重复询问。
- Modal 和 Drawer 不再因误点背景关闭，避免长表单草稿丢失。

## 9. 数据兼容

- `SCHEMA_VERSION` 保持 9，本轮没有破坏性数据迁移。
- v0.7 数据仍可直接经过既有确定性迁移进入当前版本。
- 新增任务视图、草稿状态和界面折叠均为运行时 UI 状态，不改变持久化协议。
