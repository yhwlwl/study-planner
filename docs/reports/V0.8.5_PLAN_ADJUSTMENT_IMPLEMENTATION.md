# Study Planner v0.8.5 计划调整系统实施说明

## 1. 实施目标

v0.8.5 不推翻 v0.8.4 已完成的 Goal、TaskGroup、Assignment、CalendarConstraint、PlanVersion、迁移和约束核心，而是在其上补齐“场景编排层”。

统一原则：

1. 用户已明确作出的决定只做校验，系统不得重新替用户决定。
2. 系统准备执行的任何智能改动必须先预览。
3. 默认展示一个推荐方案，用户可以比较实质不同的备选或继续生成方案。
4. 第一屏保持简洁，所有数量均可逐层展开到具体项目、原因和计算依据。
5. 桌面与手机使用同一语义和视觉状态，移动端不删减信息。

## 2. 新的处理分流

| 处理模式 | 场景 | 默认行为 |
|---|---|---|
| `validate-and-commit` | 复盘逐项顺延、批量移动、时长更新且日期仍合法 | 精确预览用户指定结果；合法项固定，只为冲突项生成替代方案 |
| `recommended-preview` | 新任务、补子任务、目标收紧、容量下降 | 准备推荐方案和一个备选，默认只展示推荐 |
| `optional-optimization` | 目标放宽、容量增加、取消限制 | 首选保持当前日期；优化由用户主动选择 |
| `exploratory-optimization` | 计划太累、主动重组未来 | 先询问用户希望得到的具体结果，再生成推荐与备选 |

内部 `Insert / Repair / Optimize / Rebuild` 继续保留，但不作为普通用户第一层概念。

## 3. 信息架构

```text
变化摘要
→ 当前计划是否可行
→ 推荐处理与主要代价
→ 问题/任务/日期/目标计数
→ 点击计数查看具体项目
→ 点击项目查看原因与计算依据
→ 比较其他方案（可选）
→ 应用预览中的改动
→ 创建可恢复版本
```

### 渐进式披露

- 第一层：`发现 5 个问题`。
- 第二层：展开五个问题的简明列表。
- 第三层：展开某个问题涉及的任务、当前值、允许值、后果和推荐处理。
- 第四层：查看为什么没有选择其他日期、约束计算和一次性例外。

信息仅折叠，不删除。

## 4. 关键行为修正

### 4.1 复盘逐项顺延

用户为 9 项未完成任务选好日期后：

- 9 项都合法：显示一次精确预览并执行；不再重排。
- 7 项合法、2 项冲突：固定 7 项，只列出并修复 2 项冲突。
- 只有用户主动比较其他方案时，才生成更广的备选。

### 4.2 目标收紧与放宽

- 收紧：推荐满足新目标的最小必要调整。
- 放宽：默认保持现有日期，不把任务自动推迟；减负或释放容量是可选优化。

### 4.3 任务插入

- 新任务与缺失子任务先尝试零移动插入。
- 必要时才移动少量自动安排任务。
- 创建前展示任务、日期、负载和目标影响。

### 4.4 旅行与容量变化

- 容量下降：必须预览修复，避免任务全部堆到范围后的第一天。
- 容量增加：默认保持当前计划，由用户决定是否用于减负或提前目标。

### 4.5 计划太累

不再直接要求选择算法偏好，而是询问可理解的结果：

- 每天少安排一些；
- 增加轻量日；
- 避免连续高负载；
- 分散长任务和高强度任务。

## 5. UI 与移动端

- 推荐方案默认展开，其他方案按需比较。
- 选中项同时使用明显边框、背景、阴影和“已选择”标记。
- 日期负载增加显示红色向上，减少显示绿色向下；容量变化单独标明。
- 手机复杂弹窗使用 `100dvh` 全屏弹性结构，正文独立滚动，底部操作保留安全区。
- 所有网格子项设置可收缩宽度，标题、日期和原因自然换行。
- 月历在手机视口内保留完整七列，不依赖横向空白或滚动。

## 6. 主要代码

- `src/lib/adjustment.ts`：事件到处理模式与偏好的场景协调器。
- `src/lib/planner.ts`：精确变更预览、固定合法选择、日期容量前后对比。
- `src/App.tsx`：统一入口、推荐与备选生成、更多方案扩展。
- `src/components/ProposalDialog.tsx`：推荐优先、渐进披露、红绿变化、逐项微调。
- `src/components/AdjustmentIntentDialog.tsx`：把抽象偏好转为用户可理解的结果。
- `src/components/ReviewDialog.tsx`：删除复盘后的重复完整重排入口。
- `src/styles.css`：选中态、全屏移动布局、七列月历和负载语义。
