# 产品升级需求完成性审查

> 审查日期：2026-08-09  
> 对照文档：`docs/PRODUCT_UPGRADE_REQUIREMENTS.md`  
> 审查范围：当前本地工作区实现、运行时验证、生产构建与桌面/手机浏览器回归

## 1. 结论

本轮已经完成“先收集、后排期”的核心闭环，以及用户指定的四项补强：导入表头映射与错误行原位修复、稳定签名缓存与摘要/解释分层、循环依赖/局部交换/真实拆分兜底、Vitest/属性测试/可注入时钟/时区/axe/CI 性能门禁。空白计划或已有计划都可以使用可恢复录入批次，连续新增、文本/CSV/XLSX 导入、批量编辑和部分安排都不会在普通保存时触发完整调度；用户主动安排时默认只计算一个推荐方案，其他方案按需生成。今日执行、历史补录、时间流水和不可变日计划基线也已接入真实统计口径。

但整份需求文档同时包含 P0、P1、P2 和长期工程目标，因此仍不能判定为“全部完成”。目前的主要缺口是：完整四步向导状态机、精确编辑位置恢复、完整 Beam Search/有限回溯、云同步 CAS、完整 JSON Schema 校验，以及通知/ICS/多计划等 P2 能力；深色模式的全站对比度深化按用户要求暂缓。

状态说明：

- ✅ 完成：主流程可用，并有实现或运行时证据。
- 🟡 部分完成：已有可用实现，但仍缺少文档中的部分子项或严格验收条件。
- ⬜ 未完成：尚未实现，或只有数据字段/占位设置而没有完整用户能力。
- ⏭️ 延后：需求本身定义为后续增强或非首轮目标。

### 3.16 用户视角真实审计

以一个手里已有任务清单、但网站还是空白的新用户为起点，按实际操作顺序检查：

1. **第一次进入**：录入页明确告诉用户先收集任务、之后再排期；可以选择粘贴、导入文件或连续创建。空批次显示“尚未录入”，不会误导成“已全部安排”。
2. **录入一半离开**：保存并退出后首页出现“继续录入”，显示未安排数量；重新进入后批次名称、任务组和汇总仍在，正式计划没有变化。
3. **连续新增**：保存并继续会保留批次并清空表单，下一条可以立即录入；轻量保存不启动排期，1000 项运行时写入 P95 仍低于 100ms。
4. **导入外部清单**：表头映射、错误行、偏好日期/固定日期和完整字段均在同一个预览内；错误数量改正后红色状态立即变为“可加入”，确认只写入批次，不直接改动正式计划。
5. **第一次生成计划**：用户可以只选择一部分任务组，系统先进入可取消的排期预览；取消预览后任务仍在批次中，正式计划不变。存在硬冲突时仍能逐项决定接受例外、重新计算或保留未安排。
6. **日常执行与突发变化**：今日页把原计划、已发生实际、剩余预计和执行负载分开解释；历史补录按记录归属日统计；未来任务提前到今天可使用一次性例外，不再被永久规则卡住。
7. **回看与带走数据**：教程包含真实产品截图，侧栏在页面滚动时固定；导出中心可按范围导出月历 CSV/ICS、统计 CSV、时间流水和打印 HTML。

审计结论：主路径已经可用且不会因中断、批量录入或导入错误污染正式计划；需要继续优化的是完整四步建档向导、精确恢复编辑位置，以及更高级的搜索式排期兜底。

## 4. 下一轮建议优先级

1. **完成首次建档向导**：把当前可跳转的准备度提示升级为可中断、可恢复的四步状态机，并补齐目标/容量/特殊日期摘要。
2. **补算法搜索兜底**：在局部交换之外，增加小预算有限回溯或 Beam Search，并补齐拆分的最小单次时长、最大段数约束。
3. **加强云端数据安全**：CAS/远端版本、冲突副本与严格 JSON Schema 导入。
4. **再进入 P2**：完整重复任务、通知、ICS、多计划和只读分享。
5. **继续质量建设**：积累并发性能样本、补内存峰值与取消时延指标，并逐步提高核心纯函数覆盖率。

## 5. 最终判定

本轮可以判定为：**用户指定的导入、性能、算法兜底和质量门禁目标已完成；P0 核心闭环已可用，日常时间与历史可信度关键问题已修复，部分 P1/P2 已提前实现；整份长期需求尚未全部完成。**

最重要的原始问题——“连续新增任务很慢、建档未完成如何继续、已有计划突然新增很多任务怎么办”——已经由通用录入批次与主动统一排期解决，不再依赖 20 个或任何固定数量阈值。
