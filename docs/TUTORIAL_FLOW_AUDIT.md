# 交互式新手教程：完整流程与异常操作审计

> 审计对象：`tutorial:v1` 交互式教程空间  
> 审计目标：不同用户、不同进入时间和常见误操作下，教程主线保持一致；教程失败不得污染真实游客/账号计划；所有智能排期仍遵循“先预览、后应用”。

## 1. 核心不变量

1. **数据隔离**：教程只在独立 `tutorial:v1` 数据空间运行，不把教程任务上传到账号云端，也不覆盖游客/账号真实计划。
2. **固定剧情**：同一教程版本使用固定 fixture、相对日期和确定性 checkpoint。进入日被锁定为教程 `anchorDate`，跨午夜不改变剧情。
3. **一步一事**：引导阶段每个步骤只开放完成当前目标所必需的操作；用户随时可以退出或重新开始。
4. **真实预览**：修复、录入排期、复盘顺延、未来重排都生成真实 `SchedulingProposal` 预览，预览状态就是最终应用状态。
5. **业务层防护**：限制不仅存在于按钮层；`AppContext` 对普通 commit、undo、直接 mutation、版本恢复等继续做教程白名单校验。
6. **可恢复**：刷新、关闭弹窗、取消 proposal、瞬态步骤中断、教程状态损坏都回到最近的安全 checkpoint，而不是猜测继续。
7. **历史保护**：教程中的已完成任务、锁定任务、历史实际用时不得被修复/未来重排改写。
8. **结束安全**：退出教程时必须先成功切回真实数据空间，再清除教程 session；原计划读取失败时保持教程可重试，不用空白状态覆盖原计划。

## 2. 标准路线

| 阶段 | 用户动作 | 必须看到/发生 | 稳定 checkpoint |
|---|---|---|---|
| 1 | 打开计划调整入口 | 固定显示 3 类问题：过去未完成、今天超载、目标期限风险 | `repair-entry` |
| 2 | 选择“修复当前问题” | 只能走当前问题修复，不暴露未来重排等无关入口 | `repair-action` |
| 3 | 查看并应用修复预览 | 已完成/锁定任务不动；逾期、超载、目标风险被修复 | `goal` |
| 4 | 查看目标 | 固定目标展示期望/最晚日期与关联任务 | `goal` |
| 5 | 进入录入 | 固定出现“刚收到的新作业”批次，不能增删改导入 | `intake` |
| 6 | 生成并应用排期预览 | 新任务正式进入计划；既有计划只按固定低扰动结果变化 | `execute` |
| 7 | 完成指定今日任务 | 只能完成教程指定任务；实际用时默认 52 分钟，可在 1–65 分钟内修改 | `review-entry` |
| 8 | 结束今天并复盘 | 复盘只聚焦未完成项，不展示无关统计/时长建议干扰 | `review-carry` |
| 9 | 顺延未完成任务并应用预览 | 只允许合法的 `今天 + 1`；确认后写入复盘记录 | `future-entry` |
| 10 | 再次打开计划调整 | 当前问题已清零，引导转为“重新安排剩余计划” | `future-entry` |
| 11 | 生成未来重排预览 | 使用固定“均衡”取舍；已完成和锁定内容保持不变 | `future-preview` |
| 12 | 应用并结束 | 显示“目标 → 排期 → 执行 → 复盘 → 调整”闭环 | `complete` |
| 13 | 开始我的计划 / 继续看看 | 前者回真实干净空间；后者进入可自由探索但仍隔离的教程空间 | 退出 / `free` |

## 3. 用户误操作审计

### 3.1 导航与页面

| 操作 | 预期结果 |
|---|---|
| 点击当前步骤无关的侧栏模块 | disabled 或被 `navigate()` 拦截，显示轻提示，不改变步骤 |
| 打开手机侧栏后点错误模块 | 关闭侧栏并保持当前步骤 |
| 今日页点前一天/后一天 | 教程阶段禁用 |
| 今日页添加任务、打开月历、批量顺延 | 教程阶段隐藏 |
| 使用浏览器返回/前进 | SPA 内不依赖 URL 作为教程真相；状态由 session/checkpoint 决定 |
| Coachmark 指向元素不在可视区域 | 自动滚动到目标，仍允许页面自然滚动 |

### 3.2 任务执行

| 操作 | 预期结果 |
|---|---|
| 点击非指定任务完成 | 按钮禁用/无动作 |
| 拖动任务 | 教程阶段 TaskCard 不可拖动 |
| 打开任务更多操作 | 教程阶段隐藏 |
| 尝试锁定、删除、修改日期、启动无关计时 | UI 不提供；业务层普通 mutation 继续拦截 |
| 指定任务实际用时留空、0、负数、超过 65 | 不能提交 |
| 合法修改为 1–65 分钟 | 可以提交且 checkpoint 仍有效 |
| 连续双击完成 | 业务步骤推进按 expected-step 幂等，第二次不会跨两步 |

### 3.3 目标与录入

| 操作 | 预期结果 |
|---|---|
| 新建/编辑/归档/删除目标 | 教程目标步骤隐藏这些入口 |
| 教程目标缺失（异常状态） | 健康检查恢复 checkpoint；空状态也不暴露“创建第一个目标”绕路 |
| 新增/编辑/删除录入批次内容 | 教程录入阶段禁用/隐藏 |
| 文件导入、AI/批量导入、选择部分项 | 教程阶段不开放 |
| 教程批次被异常删除 | 健康检查重建该步骤标准数据；空状态不暴露普通录入入口 |
| 重复构造教程新增任务 | 先清理 canonical IDs，再创建一次，不产生重复任务 |

### 3.4 调整与 Proposal

| 操作 | 预期结果 |
|---|---|
| 修复阶段选择其他调整原因 | 不显示/不允许 |
| 未来重排阶段改成其他策略 | 教程固定“均衡” |
| 在 Proposal 中“保留当前”“生成更多”“逐项微调” | 教程阶段隐藏 |
| 关闭修复 Proposal | 回 `repair-entry` 安全重试 |
| 关闭录入 Proposal | 回 `intake`，不把任务偷偷应用 |
| 关闭复盘 Proposal | 回 `review-entry`，复盘未提交 |
| 关闭未来重排 Proposal | 回 `future-entry` |
| Proposal 计算/构造结果不满足 checkpoint | 不应用；自动回对应恢复步骤 |
| 重复应用同一 proposal | expected-step + transition lock 防止跨步和重复应用 |
| 尝试直接调用普通 apply/undo/restore | `AppContext` 引导白名单阻断 |

### 3.5 今日复盘

| 操作 | 预期结果 |
|---|---|
| 提前点“结束今天并复盘” | 非 `review-entry` 时入口不开放 |
| 关闭 Review | 回 `review-entry`，可重新打开 |
| 未给未完成任务选择去向就提交 | 主按钮禁用 |
| 选择其他任意未来日期 | 教程只提供 planner 验证过的 `anchor + 1` |
| 选择的 `anchor + 1` 因规则变化不再合法 | checkpoint 健康检查失败并恢复，不强塞任务 |
| 选择“保留逾期”或“获取更多方案” | 教程隐藏，普通产品流程不受影响 |

## 4. 生命周期与恢复审计

| 场景 | 预期行为 |
|---|---|
| 在任一稳定 checkpoint 刷新 | 读取 `tutorial:v1` session 与数据，验证健康后从同一步继续 |
| 在 `repair-action/preview` 刷新 | 回 `repair-entry` |
| 在 `intake-preview` 刷新 | 回 `intake` |
| 在 `review-carry/review-preview` 刷新 | 回 `review-entry` |
| 在 `future-action/future-preview` 刷新 | 回 `future-entry` |
| 关闭标签页后重新打开 | 与刷新相同；不依赖内存弹窗状态 |
| localStorage session JSON 损坏 | 丢弃坏 session，不执行未知步骤 |
| session 教程版本不匹配 | 丢弃旧 session，避免新代码接旧剧情 |
| anchorDate 非法 | 丢弃 session |
| IndexedDB 中教程数据缺失/损坏 | 用当前步骤 canonical checkpoint 恢复 |
| 教程运行中真实时间跨 00:00 | `todayISO()` 继续返回 anchorDate，剧情不换天 |
| 教程本地写入失败 | 当前标签页继续运行并提示；刷新后仍可由 session/checkpoint 重建 |
| 原真实计划读取失败时退出 | **不清除教程 session**，不覆盖原数据，提示稍后重试 |
| 教程空间清理失败 | 不阻断已经成功完成的数据空间切换 |

## 5. 账号、游客与云同步审计

| 场景 | 预期行为 |
|---|---|
| 全新游客首次访问 | 自动进入教程；教程使用独立 namespace |
| 已有游客计划手动重玩教程 | 先持久化游客当前状态，退出后恢复游客空间 |
| 已登录且已有个人计划重玩 | 返回 namespace 记录账号空间，教程期间不上传教程 state |
| 新账号云端为空选择“体验完整流程” | 进入教程而不是先造 demo 账号计划 |
| 新账号教程完成 | 创建独立空白账号计划，再尝试初始化云端 |
| 新账号教程中途退出 | 返回首次账号起点选择，不把教程当个人计划 |
| 教程中 token refresh / 重复 SIGNED_IN | 不触发数据空间切换 |
| 教程中账号身份发生变化 | 教程继续；退出时以当前真实身份重新计算返回 namespace |
| 教程中登出 | 教程继续；退出时安全回 guest |
| 教程期间普通自动云保存 | 仅精确匹配 `user:<id>` 才上传，因此 `tutorial:v1` 不上传 |
| 离线完成教程 | 本地流程可用；账号云初始化失败时保留本地空白并显示同步失败 |
| guest/account/demo/blank | 教程不改变这些空间的隔离规则 |

## 6. 移动端与可访问性审计

- Coachmark 不使用全屏遮罩，不阻断滚动；同一时刻只显示一个引导。
- Coachmark 使用 `role="region"`、明确 aria-label，并用 polite live region 更新说明。
- Coachmark 最大高度受 `100dvh` 与上下 safe-area 限制，内容过长时自身可滚动。
- 手机端宽度同时考虑左右 safe-area；禁止操作 toast 考虑 Home Indicator safe-area。
- DOM 目标离屏时才自动滚动，不持续抢夺用户滚动位置。
- 被限制的原生按钮使用 `disabled` 时不可聚焦误触；必要的退出/重开入口始终可达。
- 教程没有删除 Proposal 的解释数据；只隐藏当前剧情不允许用户修改的替代操作。
- 最终浏览器审计必须检查 `scrollWidth <= clientWidth`，避免教程自身引入横向溢出。

## 7. 算法一致性设计

教程不依赖通用调度器“刚好算出同一个故事”。每个教学动作仍经过真实事件和真实 Proposal 预览，但目标结果由固定 builder 生成并进行真实约束校验：

- `buildTutorialRepairedFrom()`：修复固定三类初始问题；
- `buildTutorialScheduledFrom()`：固定放入新录入任务；
- Review：只允许 `suggestMoveDates()` 已确认合法的 `anchor + 1`；
- `buildTutorialFutureFrom()`：固定演示未来均衡重排；
- `tutorialStateHealth()`：每个目标 checkpoint 应用前/恢复时验证。

因此同一 `tutorial:v1` 在不同用户、不同实际日期和不同历史数据下，核心任务、问题类型、步骤、修复结果和未来重排结果保持一致。

## 8. 自动验证

本教程配套三层验证：

1. `tests/tutorial.test.ts`：fixture、checkpoint、事件白名单、时钟、幂等、已完成/锁定保护等单元测试；
2. `scripts/tutorial-flow-audit.mjs`：静态审计关键限制是否仍存在，防止后续 UI 重构不小心拆掉教程保护；
3. 部署后真实浏览器 E2E：桌面 + iPhone 尺寸完整走通，并额外尝试错误导航、刷新瞬态步骤、取消/重开、横向溢出等。

### 本地验证限制

当前工作目录的 `node_modules` 是不完整占位目录，因此本地不能把 `npm test` / Vite 构建当作可信结果。实现阶段使用全局 TypeScript 对源码做严格检查，并用实际 `tutorial.ts + planner.ts` 编译产物执行 fixture/checkpoint 运行时验证。最终以 GitHub Actions 与 Vercel 构建作为完整依赖环境的补充验证。

## 9. 发布门槛

本教程提交只有在以下条件同时满足时才视为完成：

- 静态审计全部通过；
- TypeScript 源码检查通过；
- 所有稳定 checkpoint 的运行时健康检查通过；
- feature branch GitHub Actions 中教程新增问题为 0（若仓库已有无关失败，必须单独说明）；
- Vercel Preview 构建 READY；
- 桌面与手机尺寸实际浏览器主线走通；
- 至少验证一次瞬态刷新恢复、错误导航阻断、Proposal 取消恢复、教程退出恢复真实空间；
- `main` 未被修改。
