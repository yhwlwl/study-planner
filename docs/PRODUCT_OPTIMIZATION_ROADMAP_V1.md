# Study Planner 1.0 产品与工程升级路线

> 分支：`preview`
> 建立日期：2026-08-13
> 本轮目标：完成六个阶段的核心改造，并以真实行为测试、性能门禁和用户场景审查作为验收依据。

## 1. 为什么要做这轮升级

Study Planner 已经具备“录入任务 → 生成计划 → 每日执行 → 复盘调整 → 统计导出”的完整闭环。当前主要风险不再是缺少入口，而是功能复杂度增长得比数据可靠性、交互可理解性和工程边界更快：

- 历史统计的计划快照已被冻结，但完成状态仍可能被任务后来发生的变化反向改写。
- “真实学习时间”“推断时间”“完成但未填写时间”在不同页面中的含义还不完全一致。
- 本地、备份和云端数据主要依靠宽松迁移，缺少统一的结构验证、隔离和恢复路径。
- 云同步使用最后写入覆盖，两个设备同时编辑时存在静默丢失修改的可能。
- 首次建档可用，但中途退出、重复空批次、表单续填和大批量导入仍不够顺畅。
- 今日页、月历和任务列表在手机及大数据量下的信息密度和性能还可以进一步收敛。
- 调度器速度较快，但复杂约束下找不到方案时，用户只能看到冲突，无法用明确代价和系统协商。
- 自动化检查数量不少，但核心调度、统计、同步和恢复行为的真实测试覆盖仍不足。

本轮遵循四项原则：

1. **数据可信优先于功能数量**：任何优化都不能让历史、时间或云端修改变得不可解释。
2. **黑色标题写动作，灰色说明写场景和结果**：界面首先回答“点击后会做什么”。
3. **先预览、后生效、可恢复**：涉及计划或数据的批量修改必须可比较、可撤销。
4. **同一指标只有一个定义**：今日页、统计、CSV、PDF、图片导出使用同一统计内核。

## 2. 总体验收矩阵

| 领域 | 目标 | 必须通过的证据 |
|---|---|---|
| 数据 | 历史状态不会被未来修改反写 | 跨日完成、跨日补录、旧数据迁移行为测试 |
| 本地恢复 | 损坏数据不会白屏 | Schema 拒绝、隔离、回退和下载备份测试 |
| 云同步 | 并发编辑不会静默覆盖 | revision 条件更新和冲突副本测试 |
| 首次建档 | 可中断、可续录、不堆空批次 | 空白用户完整场景测试 |
| 手机 | 375px 无横向溢出，主要操作可触控 | 真实页面视口与 axe 测试 |
| 调度 | 复杂场景可解释、结果稳定 | 真实约束基准、找解率和无关移动量门禁 |
| 导出 | 与统计页同口径，长内容稳定分页 | 90 天 / 1000 项导出测试 |
| 架构 | 核心模块可独立测试和按需加载 | Bundle、覆盖率和依赖边界门禁 |

## 3. 第一阶段：数据与可靠性底座

这是本轮最高优先级。后续体验和算法优化都建立在统一的数据口径之上。

### 3.1 统一执行时间账本

- `TimeEntry` 是实际学习时间的唯一事实来源。
- 每条记录具有明确的归属日期，不再仅由创建时间隐式推断。
- 计时、手动补录、完成时填写、旧数据残余和系统推断分别标记来源。
- “今天已发生实际”只统计归属今天且属于真实来源的分钟。
- 用户从今天返回昨天并补录 50 分钟，这 50 分钟归入昨天。
- 同一任务可以在多天学习，每天分别累加；任务当前总实际时间是全部真实记录之和。

### 3.2 冻结历史执行状态

- 每日基线继续保存当日原计划。
- 增加“截至当日”的执行状态或等价的不可变事件口径。
- 昨天未完成、今天完成，不会把昨天历史统计改成已完成。
- 对迁移前无法精确恢复的历史显示“估算”或“数据不完整”，不伪装成精确值。

### 3.3 真实时间与推断时间

- 完成任务但未填写时间时，不制造“真实学习分钟”。
- 系统可以生成推断分钟用于容量解释，但必须单独展示、可补正、不能混入真实统计。
- 报告和导出分别列出真实、推断和无时间记录完成数。

### 3.4 严格数据 Schema 与迁移

- 为完整 `AppState` 建立 Zod Schema。
- JSON、IndexedDB、Supabase 数据都经过“解析 → Schema 验证 → 版本迁移 → 归一化”。
- 无法验证的数据进入隔离区，不直接进入 React 状态。
- 每次迁移前保留原始可下载备份，并记录迁移结果和警告。

### 3.5 云端 revision 条件更新

- Supabase 快照增加单调递增的 `revision`。
- 上传时携带最后读取的 revision，只在 revision 未变化时更新。
- 冲突时保留本地与云端两个版本，提示用户选择、比较或下载，而不是静默覆盖。

### 3.6 错误与更新恢复

- 增加全局 Error Boundary。
- 错误页提供重新载入、进入恢复中心、下载本地原始数据和重置到安全副本。
- PWA 更新先提示，用户可在完成当前输入后刷新；不在输入过程中自动重载。

### 第一阶段验收

- [ ] 昨天未完成、今天完成，不会改变昨天的历史完成结果。
- [ ] 跨日期补录始终归到用户选择的日期。
- [ ] 完成但未填写时间不会计入真实分钟。
- [ ] 两台设备同时修改不会静默覆盖。
- [ ] 损坏备份不会导致白屏。
- [ ] 每次数据迁移前自动保留可下载备份。
- [ ] PWA 更新不会打断未保存输入。

## 4. 第二阶段：首次建档与录入效率

### 4.1 可中断首次建档

- 首次流程保存当前步骤、批次、草稿字段和最近编辑项。
- 重新进入时回到原步骤，并解释哪些内容已保存。
- “可用时间”只有用户主动确认后才标记完成。
- “保存并退出”返回有意义的继续入口，不跳到空任务页。

### 4.2 批次生命周期

- 创建录入时优先复用当前空批次。
- 同一天同名空批次不重复创建。
- 已安排批次保留记录，但默认折叠。
- 退出、归档、恢复和删除的差异用明确动作说明。

### 4.3 连续录入与大导入

- 保存正在填写的独立任务/任务组表单草稿。
- “保存并继续新增”保留科目、分钟、优先级等可复用字段。
- 录入 100 项期间不运行完整排期，只更新轻量摘要。
- 500 行导入预览使用分页或虚拟化，错误行可原位修复。
- 提供示例、表头映射、完整字段解释和首次排期准备度检查。

### 第二阶段验收

- [ ] 空白用户 5 分钟内可生成第一份计划。
- [ ] 中途关闭后能回到原批次、原步骤和原字段。
- [ ] 录入 100 项时不触发完整排期。
- [ ] 500 行导入编辑无明显卡顿。
- [ ] 不会无意创建多个同名空批次。

## 5. 第三阶段：日常使用和手机体验

### 5.1 今日页单主行动

- 今日页首屏只突出一个下一步动作。
- 冲突、逾期、待安排和复盘等次级提醒收进“待处理事项”。
- 顶部“N 个问题需处理”直接进入问题修复，而不是泛化入口。

### 5.2 手机信息架构

- 手机默认周列表；月视图只显示负载、完成状态和任务数量概览。
- 取消依靠极小文字展示完整月历任务。
- 删除、锁定、归档等低频操作收进更多菜单。
- 所有触控目标至少 44×44 CSS 像素。

### 5.3 大任务量与批量管理

- 任务页加入分页或虚拟列表。
- 增加批量完成、批量锁定、批量归档。
- 搜索、筛选和统计摘要不因列表虚拟化改变。

### 5.4 无障碍

- Drawer、全屏页和弹窗具备焦点陷阱、Esc 关闭和焦点恢复。
- axe 检查运行在真实应用路由和实际组件树上。
- 统一最小字号、对比度、空状态和键盘操作。

### 第三阶段验收

- [ ] 375px 屏幕无意外横向滚动。
- [ ] 月历不依靠 7～8px 文字传达关键信息。
- [ ] 1000 项任务仍能流畅搜索和筛选。
- [ ] 键盘可完整操作所有主要弹窗和抽屉。
- [ ] axe 在真实页面通过约定阈值。

## 6. 第四阶段：重排与算法升级

### 6.1 分层搜索

调度器采用逐层增加成本的搜索方式：

1. 贪心候选放置；
2. 单阻塞任务局部交换；
3. 有限 Beam Search；
4. 有预算的多步局部交换；
5. 超出预算后返回可解释的不可行结果。

搜索必须可中断并运行于 Worker，主线程保持可操作。

### 6.2 动态拆分任务

- 可拆分任务不再只在创建时预生成固定分段。
- 调度阶段可根据剩余容量动态决定分段数量和分钟。
- 保留最小单次时长、最大拆分次数和连续性约束。

### 6.3 稳定缓存和复杂基准

- 用稳定数据版本签名替代反复序列化全部时间流水。
- 摘要、解释和完整方案分层计算。
- 基准加入期限、目标、依赖、锁定、偏好日期、拆分和高负载规则。
- 记录找解率、耗时、无关移动量、期限风险和结果稳定性。

### 6.4 不可行计划的量化协商

当约束无法同时满足时，系统不只显示“硬冲突”，而是生成若干具有真实代价的协商方案：

- 每天增加多少可用分钟；
- 将某个目标或任务期限推迟多少天；
- 暂停或降低多少低优先级任务；
- 允许哪些任务拆分，以及每段多长；
- 允许使用哪些缓冲日或兼容上限；
- 在保持期限的前提下，需要减少多少总工作量。

每个方案显示：解决的冲突、仍存在的风险、影响任务数、移动任务数、增加分钟/推迟天数和为什么推荐。用户确认后才修改条件并生成精确预览。

### 第四阶段验收

- [ ] 500 项复杂场景预览 P95 小于 800ms。
- [ ] 算法运行时页面仍可操作和取消。
- [ ] 已知可行场景找解率达到 99%。
- [ ] “尽量保持现状”的无关移动量不高于当前版本。
- [ ] 同一输入重复计算结果稳定。
- [ ] 不可行方案至少返回一个可执行的量化协商路径，或明确证明无可调整项。

## 7. 第五阶段：统计、报告与复盘

### 7.1 统一统计内核

- 历史统计使用“截至当日”的执行状态。
- 今日、统计、CSV、PDF、长图使用同一聚合函数。
- 所有指标提供口径说明和数据质量标记。

### 7.2 周复盘

- 汇总原计划、真实时间、推断时间、完成率、延期、负载和科目分布。
- 识别持续的预计时长偏差和过载模式。
- 每条建议跳转到对应操作：校准时长、调整容量、修改期限或重排。

### 7.3 稳定报告导出

- 用户可保存报告模块和长图列模板。
- 超长任务表自动分片/分页，规避 Canvas 尺寸和像素上限。
- PDF 包含目录、页码、日期范围、生成时间和口径说明。
- 显示真实时间、推断时间、计划外执行和无记录完成。

### 第五阶段验收

- [ ] 同一指标在统计页、PDF、CSV、今日页完全一致。
- [ ] 无法精确恢复的历史明确标记为估算。
- [ ] 90 天和 1000 项任务导出稳定。
- [ ] 周报建议可跳转到对应操作。

## 8. 第六阶段：架构和性能收敛

### 8.1 模块边界

- `App` 拆成应用壳、页面路由和按需加载页面。
- `AppContext` 拆成任务、录入、执行、同步、版本等领域操作。
- 调度器拆成索引、约束、候选、搜索和解释。
- 导出拆成 CSV、ICS、报告、图片和共享统计模型。
- CSS 拆成基础、组件、页面、响应式和打印层。

### 8.2 体积和测试门禁

- 所有页面和大型弹窗按需加载。
- CI 检查主包、统计页和 PWA 预缓存体积。
- 核心领域使用行为测试、属性测试、时区测试和可注入时钟。

### 第六阶段目标

- [ ] 主包 gzip 小于 200KB。
- [ ] 统计页 gzip 小于 100KB。
- [ ] PWA 首次预缓存约 2.5MiB 或更低。
- [ ] 核心领域行为覆盖率达到 70% 以上。
- [ ] 调度、统计、同步关键模块分支覆盖率达到 60% 以上。

## 9. 本轮提交策略

| 提交 | 内容 | 回滚边界 |

| 1 | 路线文档、Schema、执行账本、历史口径 | 数据模型和迁移 |
| 2 | 云端 revision、Error Boundary、恢复中心、PWA 更新 | 同步与运行时可靠性 |
| 3 | 首次建档、批次和大导入 | 录入流程 |
| 4 | 今日页、手机、任务列表和无障碍 | 日常 UI |
| 5 | 搜索、拆分、缓存和量化协商 | 调度算法 |

每个提交必须至少满足：TypeScript 构建通过、相关行为测试通过、迁移有旧数据样例、用户已有 README 和图片不被覆盖。

## 10. 完成性审查方法

本轮结束时按三层审查：

1. **代码审查**：逐项对应本文件中的任务和验收标准，标记完成、部分完成或未完成，并链接实现与测试。
2. **自动门禁**：执行单元测试、行为测试、构建、Bundle 检查、调度基准、导出压力测试和真实页面 axe。
3. **用户旅程**：以全新用户、长期用户、跨设备用户和手机用户四个身份完成从录入到复盘导出的真实操作。

未通过的项目不能仅用“已有入口”判定完成；必须说明缺口、影响和下一步。
